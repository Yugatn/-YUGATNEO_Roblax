## 1. Конечный результат глазами игрока

Игрок впервые попадает в **YUGATNEO MATRIX**, а не на одинокую шахматную доску. Он видит высокий мир-серпантин с **тремя видимыми витками пространственной спирали**, центральную **Ось Икс**, неоновую голограмму «YUGATNEO MATRIX» над городом и последовательность доступных для исследования площадок. Из стартовой точки можно дойти пешком до верхнего витка, остановиться у ориентиров и вернуться обратно.

На втором витке игрок встречает **шахматный портал**: подходит к нему, получает понятную подсказку о режиме, подтверждает вход и переходит в существующее шахматное измерение. После партии он может вернуться в хаб через отдельную безопасную точку выхода (в финальной меж-place архитектуре — отдельный портал на сервере Chess Place). 

На первом витке находится **телефонная будка** — визуальный анонс будущего пути «цифровой код → A–B → пробуждение → Зион». Пока тот мир не создан, будка **не должна телепортировать в несуществующее место**: интерфейс честно сообщает «Мир готовится». Это даёт проверяемую сцену сейчас, не обещая уже готовый «Зион».

### Критерий «готово» для HUB-001

> **Один отдельный Hub Place построен и собирается, три витка реально проходимы, центральный ориентир виден, портал шахмат отображает статус и безопасно переводит игрока в существующий Chess Place после публикации обоих Places, а ошибочный переход не оставляет игрока без управления или объяснения.**

Статический скриншот концепта, текстовая карта миров, успешный `rojo build` или появление одного портального макета **не достаточны**.

## 2. Что уже есть и что нельзя ломать

**Существует в репозитории:**
- `src/server/ChessArena.server.lua` — строит одну общую шахматную доску и серверную логику;
- `src/server/ChessRules.lua` — правила, проверки шаха, мата и пата в прототипе v0.2;
- `src/client/ChessControls.client.lua` — управление;
- `src/server/CoopWaveDirector.lua` — независимый, пока не запущенный модуль волн;
- `default.project.json` — **нынешняя шахматная сборка** Rojo;
- `.github/workflows/roblox-ci.yml` — автоматическая сборка и **только вручную включаемая** публикация.

**Обязательная входная проверка («Gate 0»):**
1. Запустить `default.project.json` в Roblox Studio с **Server + 2 Players**.
2. Подтвердить на реальных клиентах назначение White/Black, легальные ходы, запрет чужого хода, шах/мат/пат, превращение пешки и reset с двумя подтверждениями.
3. Записать найденные дефекты; критичные устранить до интеграции нового портала.
4. Зафиксировать коммит, результат CI и краткий протокол тестов. **Успешная Rojo-сборка не доказывает работу шахмат в Studio**.

**Правило разделения:** Нельзя просто добавить Hub-генератор в текущий `default.project.json`, оставив `ChessArena.server.lua` там же: тогда хаб автоматически будет создавать шахматную доску в том же Place и смешает две архитектурные роли. **Первым изменением сделать два изолированных Rojo-проекта:** сохранение существующей шахматной сборки + новый Hub Project, либо согласованную эквивалентную структуру с двумя отдельными Place-целями. Не менять существующее поведение Chess Place без регрессионной проверки.

## 3. Пространственная схема первой версии (проектные параметры)

### Геометрия серпантина

- **Три витка**, отличимые визуально по высоте, назначению и световой маркировке; траектория непрерывная и проходима в обе стороны.
- Ориентировочный параметрический коридор для прототипирования (не абсолютный авторский канон): `t = 0 … 6π`, `radius = 40 + (t / 6π) * 35 studs`, `height = 5 + (t / 2π) * 14 studs`. Это означает три оборота и ~42 studs подъёма. Адаптировать под устойчивый проход Roblox-аватара, пересечения и коллизии, а не слепо копировать числа.
- Проезжая/пешеходная спираль для MVP — **проходимая широкая дорожка** с надёжным полом, защитой от падения, безопасными переходами и промежуточными площадками. Рекомендуемая ширина — от 14 studs как исходная геометрическая гипотеза, уточняемая тестами; навигационные мосты и обходы не должны требовать сложного прыжка.
- Каждые ~⅓ витка — визуальный ориентир. На каждом полном витке — безопасная обзорная площадка. Декорации не блокируют движение и не вызывают случайный перенос.
- При падении — безопасное появление на ближайшей ранее достигнутой точке, **без потери иных результатов**. В MVP восстановление может жить в памяти текущего сервера; не обещать постоянное сохранение, пока не внедрён DataStore.

### Содержимое трёх витков

| Виток | Атмосфера и назначение | Минимум в HUB-001 | Продолжение в других задачах |
| --- | --- | --- | --- |
| **I — Познание** | Старт, клеточное происхождение, память, библиотека | Точка появления, табличка «Мир возможностей», ориентир библиотеки, телефонная будка со статусом «Готовится» | Кинематографическое деление клетки, библиотека, первая логическая игра |
| **II — Выбор** | Игры разума, соревнование, взаимное уважение | **Рабочий портал Chess Arena**, ясное описание «шахматы 1v1» | Шашки, зрительские трибуны, турниры, гонки |
| **III — Созидание** | Совместные действия и новые измерения | Обзорная площадка, макеты-указатели «Neon Grid», «Oblivion», «METAL SENTINELS» | Реальные порталы после создания соответствующих Places, галерея, мастерская |

**Ось Икс** — высокая внутренняя башня либо световой стержень, читаемый с любой площадки, не препятствующий движению. **Голограмма** «YUGATNEO MATRIX» — не использует сторонние защищённые логотипы и шрифты. Для слабых устройств визуальные эффекты должны иметь упрощённый режим.

### Первое впечатление (до одной минуты без принуждения)

1. Игрок появляется перед «Осью Икс» и видит три уровня над собой.
2. Удобная табличка/краткая подсказка сообщает: «Исследуй миры. Каждый путь — возможность».
3. Игрок выбирает: идти сразу к шахматам, исследовать спираль или остаться наблюдателем.
4. При шахматном портале явно видны **жанр, число игроков, действие и возможность возврата**.
5. Нет обязательной оплаты, сложной регистрации, случайного розыгрыша или «плати для входа».

## 4. Порталы: контракт и модель угроз

### Идентификаторы и разрешённые назначения

- Иметь **только серверную конфигурацию** с явным списком `portalKey → destinationPlaceId → enabled`.
- **Не угадывать и не вставлять вымышленные PlaceId.** До создания Chess Place и определения настоящего ID использовать состояние `CONFIG_REQUIRED` / «Переход пока недоступен».
- Hub и Chess Place должны принадлежать запланированной Roblox Experience либо быть законно настроены для перехода. Правила доступа к отдельным Places проверять в Creator Dashboard.
- **Не доверять** `destinationPlaceId` или `portalKey`, присланному произвольным клиентским RemoteEvent, как разрешению доступа. На сервере сверять с белым списком, правами и ближайшим настоящим объектом портала.

### Запуск

Рекомендуется `ProximityPrompt.Triggered(player)` на сервере; перед запуском повторно проверить, что игрок ещё находится рядом, портал активен и его запрос не обработан ранее. Передать пользователя через **`TeleportService:TeleportAsync(placeId, {player})` в серверном Script**, под `pcall`.

**Критично:** Roblox прямо указывает, что `TeleportService` **не работает при playtest внутри Roblox Studio**. Зональность, ProximityPrompt и валидацию проверять в Studio; настоящий меж-place переход — только после публикации тестовой Experience и запуска через клиент Roblox. Политика публикации по умолчанию — **без автоматической отправки в production**.

### Сбои и безопасный возврат

- При ошибке телепорта или неизвестном ID игрок **остаётся в Hub**, видит понятное уведомление и не попадает в бесконечный цикл попыток.
- Короткий per-player cooldown для повторного нажатия; сбрасывать блокировку после ошибки. Повторные обращения не должны запускать дубликаты параллельных переходов.
- Не доверять клиентским `TeleportData` для выдачи рейтинга, предметов или денег. В данных перехода допустимы лишь не чувствительные сигналы удобства — например, указатель исходного портала, после серверной проверки.
- Для **обратного выхода из Chess Place** нужен отдельный серверный return portal, разрешённый PlaceId хаба и понятная кнопка/подсказка. Не вырывать игрока из активной партии без осознанного действия; уход обрабатывается серверной игровой логикой.
- Никаких собственных ключей Roblox API в репозитории; только GitHub Actions Secrets для управляемого ручного релиза.

Источники Roblox Creator Hub: [Teleport between places](https://create.roblox.com/docs/projects/teleport), [TeleportService](https://create.roblox.com/docs/reference/engine/classes/TeleportService).

## 8. Definition of Done (что разрешает отметить следующий этап как завершённый)

1. **Код** двух отдельных Roblox Place-целей опубликован в GitHub, с версиями и инструкциями Rojo.
2. **Фактический Hub** генерируется в Studio и содержит три витка, Ось Икс, голограмму и один шахматный портал; неподключённые миры честно обозначены.
3. **В обе стороны** реально работает переход между **опубликованными тестовыми** Hub и Chess Places; сбои не ломают игру.
4. **Безопасность:** произвольный пользователь не выбирает чужой PlaceId, не телепортирует других и не обходит проверку расстояния.
5. **Совместимость:** Chess v0.2 проходит регрессию с двумя клиентами.
6. **Доказательства:** успешные GitHub Actions, ручной игровой протокол, известные ограничения и при возможности видеозапись.
7. **Документация:** README и матрица миров содержат **проверенный** статус, а не статус «готово» заранее.
