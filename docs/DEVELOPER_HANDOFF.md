# Передача проекта специалистам: техническая архитектура и ручная сборка

**Главный принцип передачи:** даже если исходный код перестанет работать, этот документ вместе с `WORLD_BIBLE_RU.md` и `GAME_MODES_AND_ROADMAP.md` должен позволить собрать первый выпуск в Roblox Studio.

## 2. Как собрать в Roblox Studio вручную, без терминала

1. Создать **новый тестовый Roblox experience**, не редактировать действующую публичную игру непосредственно.
2. Открыть **View → Explorer** и **View → Output**. В `Workspace` удалить конфликтующие старые объекты `YUGATNEO_*` только внутри тестового place.
3. В `ServerScriptService` вручную создать объекты **ModuleScript** для всех файлов с окончанием `.lua`: `ChessEngine`, `MatchTable`, `TournamentHub`, `Rankings`, `ArcadeLibrary`, `RetroEngine`, `BookCatalog`, `RewardService`. Вставить полный код каждого файла из GitHub.
4. Создать объекты **Script** для всех серверных файлов с окончанием `.server.lua`: `StoryXMatrixWorld`, `SpiralWorld`, `SpiralVehicles`, `ChessArena`, `CognitiveArcade`, `RetroArcade`, `StoryXLibrary`. Вставить соответствующее содержимое.
5. В `StarterPlayer > StarterPlayerScripts` создать **LocalScript** для каждого файла `.client.lua`, назвав их в соответствии с ключами `default.project.json`. Вставить код.
6. В `Workspace` при желании оставить только нейтральный Baseplate: остальные платформы, портал, стойки, картины, книжные шкафы, доски и автомобили генерируются серверными скриптами.
7. Запустить **Play** и проверить **Output**. Устранить первую ошибку до остальных: остановка первичного серверного модуля может мешать всей цепочке.
8. В **Test → Start** использовать минимум 2 клиента для файтинга/шахмат и 4 клиента для шахматного турнира. Восстановить работоспособность по сценарию `ACCEPTANCE_TESTS.md`.
9. Только после успешных тестов и оценки безопасности перенести проверенные изменения из черновой ветки в `main`, затем в целевой опубликованный Roblox place.

### Альтернативный способ через Rojo

Установив Rojo и плагин, переключиться на `feature/story-x-spiral-chess-tournaments`, запустить `rojo serve default.project.json` и подключить Roblox Studio. GitHub-коммит **сам по себе не пересылает файлы в Studio**, необходим локальный fetch/pull. Не подключать Rojo к живой игровой сессии со старыми данными без резервной копии.

## 3. Устройство жизненных циклов

**Загрузка:** сгенерировать карту → зарегистрировать RemoteEvents → подготовить таблицы и устройства → подгрузить профиль игрока асинхронно. `ModuleScript` может требовать DataStore при `require`, поэтому потенциальные задержки должны быть изолированы от игрового UI.

**Начало мини-игры:** сервер проверяет реальное положение игрока, тип задания, что игрок не находится в шахматном матче, и отсутствие несовместимой активной сессии. Выдаёт session ID и публичные данные без ответа. Хранит правильный ответ у себя.

**Действия клиента:** отправляет только `action` и безопасный ограниченный набор аргументов. Никакой `score`, `winner`, `coins` от клиента не принимается.

**Конец:** сервер проверяет условие победы, единожды выдаёт монеты, уведомляет клиента, очищает сессию и отключает все эффекты. При отключении игрока — убрать его из очередей, освободить место, прекратить участие.

**Данные:** сохранение косметики и монет через `DataStoreService.UpdateAsync`; лидерборд побед через `OrderedDataStore`; персональные заметки отдельным ключом по `UserId`. Для рангов и кросс-серверной очереди использовать соответствующее хранилище **только после анализа ограничений, стоимости и квот**, не полагаться на MemoryStore для бессрочного прогресса.

## 4. Как добавить книгу вручную

В `BookCatalog.lua` расширить массив таблицей со свойствами:

```lua
{
  id = "my_original_story",
  language = "ru",
  age = "9+",
  genre = "Логика",
  title = "Оригинальная история",
  author = "Имя разрешённого автора",
  paragraphs = {
    "Абзац 1...",
    "Абзац 2...",
    "Абзац 3...",
    "Абзац 4..."
  },
  locate = "В каком абзаце герой нашёл ключ?",
  locateAnswer = 2,
  understand = "Почему герой изменил решение?",
  answers = {"A", "B", "C", "D"},
  understandAnswer = 3
}
```

Проверить корректность ответа редактором/преподавателем. Убедиться, что `id` уникален и не меняется после появления наград. Для иностранных переводов хранить метаданные прав на **оригинал и конкретный перевод** отдельно.

Для сохранения заметок менять только серверный метод `TextService:FilterStringAsync` с `GetNonChatStringForUserAsync`, никогда не пересылать непроверенный текст в публичный чат, лидерборд или SurfaceGui.

## 5. Как добавить награду

В `RewardService.lua` добавить элемент `CATALOG` с неизменным ID и ценой. В `StoryXRewards.client.lua` добавить соответствующую видимую кнопку. В серверном `render` реализовать визуальное представление, прикреплённое к персонажу без изменения его реального Roblox-каталога. Предмет не должен менять WalkSpeed, Hitbox, дальность клика и шанс победить. Для автомобиля текущий вариант VioletKart меняет цвет корпуса только при управлении владельцем.

Важно: одноразовые достижения в `rewarded` должны иметь уникальный серверный ключ; игры не должны бесконечно печатать токены при переподключении. Ревизия сохранения и журнал операций необходимы перед большим релизом.

## 6. Как вручную создать платформу нового витка

1. Создать платформу размером от 50×50 studs в радиусе игрового мира, не внутри траектории машин.
2. Провести мост от выбранного участка серпантина, проверить уклон и коллизию. Обязательно поставить ограждения или безопасные зоны падения.
3. На переходе поставить `ProximityPrompt` с понятным названием и кнопкой выхода.
4. Сгенерировать регион мини-игры, табличку правил, зону зрителей и серверный контроллер. Дистанция взаимодействия измеряется от сервера.
5. Создать LocalScript для UI, клавиатуры, контроллера и тач-управления; тестировать медленное устройство.
6. Проверить FPS, количество Parts, стриминг пространства, доступность UI, угол обзора и безопасный возврат на spawn.
7. Принимать уровень в эксплуатацию только после ручного и автоматического QA.

## 7. Критические проблемы для дальнейшей инженерной работы

- Автоматические регрессии для шахмат, игр/заметок, привязки монет к событиям и устойчивости сетевых очередей.
- Взаимное перекрытие разных экранов HUD на телефонах.
- Блокировка промптов и корректное размораживание персонажей при телепорте, смерти и выходе из игры.
- Сохранение данных при одновременном входе на два сервера: возможны конфликтующие обновления; нужен версионированный профиль с защитой от повторного сохранения.
- Контроль частоты RemoteEvent; фильтрация произвольного текста; полное отсутствие исполняемого пользовательского кода.
- Использовать Roblox Creator Hub в качестве источника API: https://create.roblox.com/docs
- Не считать `rojo build` доказательством безопасности или правильности игровых механик: сборка проверяет только часть контрактов.

## 8. Роли будущих участников

**Luau/Backend:** шахматные тесты, очередь, DataStore, конкурентность и правовая безопасность наград.  
**Level Designer:** серпантин, транспортные развязки, укрытия, галерея, навигация и оптимизация Part count.  
**UI/UX:** мобильный ридер, большие кнопки, масштабирование шрифтов, accessibility.  
**Геймдизайнер/педагог:** задания по чтению и логике, возрастная градация, справедливость турниров.  
**Редактор/юрист по IP:** лицензии на книги, переводы, художественные репродукции, ретроигры, музыку.  
**QA/безопасность:** 4–12 клиентов, антиэксплойт, мобильные устройства, отказ хранилища, детская безопасность.

**Не менять философский канон «Сюжета Икс» без согласования с автором; оформлять сценарные ветки как отдельные предложения.**
