# STORY X: практическое руководство по ручной реализации Roblox Studio

> **Цель:** даже если будущие изменения автоматически не удастся отправить в GitHub, этот файл позволяет вручную собрать игру, понять зависимости и поручить работу специалистам. Он описывает как существующие исходники, так и дальнейшие шаги. **Все скрипты требуют живой проверки в Studio.**

## 1. Получение исходников и структура
Репозиторий `Yugatn/-YUGATNEO_Roblax`. Основная интеграционная ветка `feature/story-x-spiral-chess-tournaments`; продолжение библиотеки `feature/story-x-library-recreation`. Базовый `main` остаётся стабильной предыдущей версией, пока новые функции не пройдут проверку.

Путь через Rojo: переключить репозиторий на нужную ветку, открыть корень, запустить `rojo serve default.project.json`, в Roblox Studio установить/подключить Rojo plugin, открыть отдельный тестовый Place, проверить сервисы в Explorer, затем **Play**. При невозможности Rojo создавать вручную `Script` в `ServerScriptService`, `ModuleScript` для файлов `.lua`, `LocalScript` в `StarterPlayerScripts`. Имя объекта Roblox должно точно соответствовать ключу в `default.project.json`.

### Серверные зависимости

- `ChessEngine.lua` → ModuleScript `ServerScriptService.ChessEngine`; правила шахмат.
- `MatchTable.lua` → ModuleScript, требует `ChessEngine`.
- `TournamentHub.lua` → ModuleScript, работающий с несколькими `MatchTable`.
- `Rankings.lua` → ModuleScript, итоговые победы/хранилище.
- `ChessArena.server.lua` → Script, создаёт таблицы, очереди и экран турниров.
- `StoryXMatrixWorld.server.lua` → Script, город, миссии, дроны и терминалы.
- `SpiralWorld.server.lua` → Script, спираль, мост, порталы и центр.
- `SpiralVehicles.server.lua` → Script, тестовые машины.
- `ArcadeLibrary.lua` → ModuleScript, генерация 5 когнитивных заданий.
- `CognitiveArcade.server.lua` → Script, площадка задач/голографический тир, требует `ArcadeLibrary`.
- `LibraryCatalog.lua` → ModuleScript, тексты книг и проверочные вопросы.
- `WorldRewards.lua` → ModuleScript, серверное начисление жетонов, косметика и сохранение.
- `LibraryWorld.server.lua` → Script, требует `LibraryCatalog` и `WorldRewards`.
- `RetroEngine.lua` → ModuleScript, базовые правила оригинальных Snake и файтинга. Snake имеет работающий игровой автомат по исходному коду; файтинг пока только движок.
- `RetroArcade.server.lua` → Script, создаёт 8-битный автомат Spiral Snake и серверный игровой цикл. Требует `RetroEngine` и `WorldRewards`.

### Клиентские зависимости

- `ChessControls.client.lua` — матч, управление шахматами.
- `ChessCommunity.client.lua` — зрители, турнирная сетка и очереди.
- `StoryXMatrixHUD.client.lua` — задания, память и тренировка.
- `CognitiveArcade.client.lua` — UI логических задач.
- `LibraryReader.client.lua` — книги, локальные заметки, гонка чтения, витрина наград.
- `RetroArcade.client.lua` — интерфейс Snake, кнопки для телефона, перенаправление клавиш стрелок и WASD.

Проверить, что в клиентском Output нет `Infinite yield possible on WaitForChild`. Любая ошибка загрузки `require` может помешать запуску механики; исправлять сверху вниз по зависимостям.

## 2. Геометрия: позиции и ручная замена процедурного мира

Старт Matrix около `(0,0,0)`; шахматный зал/серпантин около `(500,0,0)`; когнитивная аркада около `(104,0,30)`; детская библиотека около `(-139,0,64)`.

**Если скрипт геометрии не работает:** в `Workspace` вручную создать `Model` с уникальным названием `StoryX_Spiral_Manual`. Центральная шахматная платформа должна поддерживать физические фигуры, проходы и зрителей. Дорожный серпантин создать из последовательных `Part` или `MeshPart` с `Anchored=true` (для поверхности), `CanCollide=true`. Каждый сегмент трассы должен стыковаться с соседями без разрыва. Использовать несколько витков вокруг координаты X=500. По наружной и внутренней кромке установить сплошные видимые ограждения; верхний виток завершить площадкой с дорожкой выхода. **Не рассчитывать на прямые наклонные ступени от шаблона без проверки** — их геометрию надо испытать на персонаже и машине.

Портал в библиотеку не заменяет пешеходный маршрут; соединить мостом старт и восточную сторону библиотеки. Сохранить широкие выходы, чтобы игрок мог добровольно покинуть библиотеку в любой момент.

**Шахматный зал:** доски 1 и 2 — полуфиналы, доска 3 — свободная партия; доска 1 снова используется в финале. Доски физически разнести так, чтобы персонажи и камеры не пересекались. UI зрителя не должен перехватывать управление чужим матчем.

## 3. Библиотека: ручная сборка и сценарий

Создать `Model LibraryX` → `Floor`, `Bookshelves`, `ReadingTables`, `StudyDesks`, `RaceKiosk`, `PrizeCounter`, `ArtGallery`, `ExitPortal`. Минимум четыре книжные полки. Каждый том — объект `BookVolume` с `StringValue BookId`, атрибутами `Title`, `Author`, `AgeRange`, `Language`, `Rights`. Для книги подгружается список абзацев из одного заранее проверенного модуля `LibraryCatalog`.

Триггер на полке — `ProximityPrompt`; скрипт сообщает клиенту ID. GUI для чтения показывает полное название, нумерованные абзацы, выбор одного абзаца, вопросы и локальные заметки. Для детского режима: минимальный кегль 16–18 относительно реального разрешения, контраст, отсутствие мелькания, настройка крупного текста, возможность скрыть таймер.

**Соревнование:** дать игрокам 10–15 секунд на регистрацию, 60 секунд на поиск. Использовать один серверный объект `challenge` с закрытыми правильными `BookId/ParagraphId/AnswerId`. Клиент знает вопрос и варианты ответов, но не видит правильные ID. После проверки сервер сохраняет точное время, начисляет жетоны победителю и награды участникам. Важно тестировать одновременное финиширование и отключение игроков.

**Заметки:** первая версия хранит текст **локально в текущем сеансе**. Они не уходят на сервер и не входят в глобальный рейтинг. Перед сохранением и показом текстовых заметок другим пользователям потребуется `TextService:FilterStringAsync`, правильный способ получения текста для конкретного пользователя, лимиты символов, обработка ошибок и согласие на сохранение. Не отправлять неотфильтрованный UGC в RemoteEvent других игроков.

## 4. Награды и игровые предметы

Схема `WorldRewards`: `coins`, `owned`, `equipped`, уникальные основания начисления. Сервер вызывает `award(player, amount, reason, receipt)` **только после подтверждённой победы/прохождения**. Клиент может послать только `Buy` или `Equip`, никогда произвольное начисление. Базовые косметические предметы: `Glasses`, `Crown`, `Trail`; `KartCyan` зарезервирован для следующей интеграции с транспортом, поэтому его нельзя рекламировать как готовую модификацию.

На старте можно хранить очки в памяти сервера. Для постоянного сохранения использовать `DataStoreService` в отдельном тестовом Universe, `GetAsync` на входе и атомарный `UpdateAsync` на записи; нужны очереди, защита от двойного расходования, проверки конфликтов, повторные попытки и тест кросс-серверных гонок. Не передавать игрокам реальные деньги, Robux или ценные объекты за детские успехи. Речь исключительно о **внутриигровых наградах**.

## 5. Картины и музейная экспозиция

На стенах библиотеки разместить 4–8 собственных пиксельных полотен. Для каждой картины создать `ArtCard` с названием, `Artist`, `Year`, `Rights`, `LearningQuestions`. Открытие кнопкой E. Картины первой версии генерируются обычными `Part` без внешних изображений — это просто оригинальные абстрактные композиции. Позже возможны репродукции старых художников и атрибутированные CC0-изображения после проверки прав именно на файл изображения.

## 6. Гонка, прятки, догонялки, шашки — контракт для отдельного исполнителя

Каждая мини-игра реализуется как `MiniGameDefinition`: `id`, `version`, `arena`, `minPlayers`, `maxPlayers`, `state` (`Lobby/Countdown/Playing/Finished/Cleanup`), `join`, `leave`, `handleAction`, `getPublicState`, `endRound`. Передавать только безопасные данные через `RemoteEvents`. Все игровые результаты считать на сервере.

Прятки: добровольная группа, фаза подготовки, антиспойлер камеры, серверное обнаружение цели, зрители после нахождения, время на поиск. Догонялки: водящий, антиспам касаний, краткий иммунитет, серверный таймер. Казаки-разбойники: две команды, маскировка и условные следы, запрет вреда игроку. Шашки: строгие правила выбранной версии, отдельный `CheckersEngine` и физическая доска, обязательные взятия, дамки, ничьи.

**Экономическая игра:** полностью авторское название/оформление, кубики, экономические ресурсы, выбор стратегии и общественные задачи; не копировать графику, текст или товарные знаки «Монополии». **Защита сада:** самостоятельная PvE-логическая игра со своим дизайном персонажей и правилами, а не дистрибуция Plants vs. Zombies.

## 7. Проверка и критические сценарии

1. Rojo build, отсутствие ошибок загрузки ModuleScript, все RemoteEvents появляются только один раз.
2. Войти двум клиентам — независимо открыть книгу; заметки одного не должны оказаться видны другому.
3. Войти 4 игрокам — запустить гонку; одним неверно ответить, двумя одновременно дать правильный ответ, одному отключиться, убедиться, что рейтинги и жетоны считает сервер.
4. Повторно отправить один и тот же ответ; очки не должны дублироваться.
5. Проверить покупки без достаточного баланса, отправить неизвестный ItemId, спамить RemoteEvent; предметы без права и вне игры не должны появиться.
6. Отключить API Services: игровой процесс сохраняется, но сохранение между сеансами не обещается.
7. С телефоном: проверить скролл, чтение абзацев, нажатия, закрытие окон, клавиатуру заметок и пересечения с шахматным HUD.
8. Проверить маршруты между Matrix, библиотекой, аркадой, серпантином — пешком и с использованием порталов. Игрок не должен застревать.
9. Для масштабной редакции: тест с ограниченной скоростью интернета, слабым мобильным устройством, 10–20 игроками, длительной сессией, подключением/выходом в середине турнира.

## 8. Содержание библиотеки, авторские права, локализация

Начальные тексты `LibraryCatalog.lua` написаны специально для YUGATNEO. Следующая коллекция: басни и сказки Крылова, рассказы Толстого, сказки Андерсена, ранние работы Льюиса Кэрролла и др. **Важно:** статус исходника, редакции, иллюстраций и переводов проверять отдельно для стран распространения. Не вставлять «Незнайку», «Mortal Kombat», `Plants vs Zombies`, музыку или изображения коммерческих игр без лицензии. Лицензию можно получить у правообладателей и подключить произведение после проверки условий. Каталог потенциальных произведений — в `docs/LIBRARY_CONTENT.md`.

## 9. Definition of Done

Перевести фичу из `PLANNED` в `IMPLEMENTED` только после появления кода, из `IMPLEMENTED` в `TESTED` — после сохранённых результатов конкретной Roblox Studio проверки с номером коммита; в `RELEASED` — после публикации в тестовом/основном Universe и проверки разрешений. Коммит без запуска — **не готовая игра**.

Разработчику передаются: эта инструкция, `docs/STORY_X_WORLD_BIBLE_RU.md`, `default.project.json`, список ошибок из Studio Output и `docs/MATRIX_TEST_PLAN.md`.

## 10. Новый игровой автомат Spiral Snake

Внутри первоначальной карты центр ретрозоны находится около `(162,0,38)` рядом с когнитивной аркадой. Если проект собирается вручную, модуль `RetroEngine` следует создать **раньше** серверного `RetroArcade`. Сервер создаёт прямоугольный игровой автомат с `ProximityPrompt`, а клиент рисует игровую сетку 14×11. Клавиши стрелок/WASD или сенсорные стрелки управляют направлением; сервер проверяет поворот, границы и столкновения. Золотая клетка — еда, зелёные — змейка. При проигрыше сервер показывает результат и выдаёт ограниченное количество жетонов. Нажатие EXIT убирает интерфейс и возвращает клавиатурное управление персонажу.

**Отдельно протестировать:** на телефоне, при повторном входе и при выходе из автомата посередине игры. Существующий файтинг в `RetroEngine` не подключён к игровому автомату; он остаётся демонстрационным движком и не должен рекламироваться как готовая игра.
